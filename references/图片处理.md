# 图片处理

一期文章共 **15 张左右**图片，分三类来源：

| 来源 | 图 | 做法 |
|---|---|---|
| **PDF 原生位图** | 结果图、结论示意图 | 提取 → 检测面板 → 裁切拼接，**不重绘** |
| **自制** | 封面信息卡、技术路线图 | Pillow 手绘 |
| **用户提供** | 关注二维码 | 裁白边 + 补静默区 + 放大，**只做一次，之后复用** |

---

## 一、从 PDF 提取大图 + 面板检测

```bash
# SK = 本技能所在目录
SK="$HOME/.workbuddy/skills/sci-wechat-daily"

python "$SK/scripts/figtools.py" detect "<论文.pdf>" "<项目>/.cache/figs"
```

### 原理

1. 遍历每页的 `page.get_images(full=True)`，取 `page.get_image_rects(xref)` 的显示矩形；
2. **跳过宽度 < 页面宽度 50% 的图** —— 那些是 logo、页眉、图标；
3. 用 `doc.extract_image(xref)` 取**原生位图**（不是页面渲染截图，保真度最高）；
4. 对灰度图二值化（`< 244`）、两次膨胀、连通域标记，得到各面板包围盒；
5. 过滤掉过小的框（`min_w=60, min_h=40, min_area=6000`，按 1/3 缩放前的坐标）；
6. 生成标注图 `annot_p<N>.png`（每个面板画框 + 左上角标数字）。

**输出**：

```
.cache/figs/
├── p1_x123.png        ← 第 1 页抽出的原生位图
├── p1_x124.png
├── annot_p1.png       ← 带面板编号的标注图（★ 人工核对用）
├── annot_p2.png
└── panels.json        ← {page, image, annot, size, boxes:[[x0,y0,x1,y1]...]}
```

### ★ 必须人工核对

打开 `annot_p1.png`，**逐个核对框与论文里的面板字母（A/B/C…）是否一一对应**。
自动检测按「从上到下、从左到右」排序，多数期刊排版下 `boxes[0]` 就是面板 A，
但**跨栏排版、合并跨行面板会错位** —— 出错要人工在 spec.json 里改坐标。

## 一之补 · 两件自动检测搞不定的事

### A. 正文页完全没有图 → Accepted Manuscript 版式

**判据（30 秒）**：

```python
import pymupdf
d = pymupdf.open(pdf)
for i, pg in enumerate(d):
    print(i + 1, len(pg.get_images(full=True)), len(pg.get_drawings()))
```

若**正文页的位图数与绘图数同时为 0**，说明正文里根本没有插图：

- 正文（Abstract / Intro / Method / Results / Discussion）通篇无图
- 图注单独集中在一处（常见标题 `Figure legends`）
- **正文图全部排在文末**，一页一张，页面文本只有 `Figure 1` + `205x230 mm`

→ 去文末抽图，再去图注页取图注文字。

### B. 整张拼版图 → 自动切面板不准

一页只有 **1 张位图**，但内含 A–M 十多个面板时，`figtools.detect` 的连通域检测
只认得出两三个（因为面板之间的白缝**不贯通**整行整列）。

用 `panel_guide.py` 三步人工定框：

```bash
SK="<技能目录>"

# ① 粗看白缝（只是候选，别直接用）
python "$SK/scripts/panel_guide.py" grid "<大图>"

# ② ★ 叠加坐标网格，直接读刻度定坐标
python "$SK/scripts/panel_guide.py" overlay "<大图>" "<项目>/.cache/grid.png" 100

# ③ 按 boxes.json 批量裁，并拼成一张校对图，一次看完再修正
python "$SK/scripts/panel_guide.py" crop "<boxes.json>" "<项目>/.cache/pv" "<项目>/.cache/sheet.png"
```

`boxes.json` 格式：`{ "<大图路径>": { "面板名": [x0, y0, x1, y1], ... }, ... }`

> **★ 别靠"看渲染图猜比例"。** 显示器缩放不同，估算出的比例尺就不同，
> 坐标必然来回返工 —— 实测迭代了 4 轮才对，换成叠加坐标网格后一次就准。
> **★ 校对图一次看完，别一张张看** —— 14 张图拼一张 4 列的校对图，几秒扫完。

### C. 矢量主图（Nature / Science / Cell 一类）→ 渲染整页 + 按图注 y 裁剪

**判据**：`figtools detect` 只找到 Extended Data 那几页，正文主图**一张都没抽出来**；
但翻 PDF 明明每张主图都占了大半页。原因是主图由**矢量绘图（drawings）+ 几块小位图**拼成，
`detect` 只看 `get_images()` 且要求宽度 ≥ 页宽 50%，于是整页被跳过。

先用 `find_figs.py` 一页页摸清版式，**别急着下"这篇没图"的结论**：

```bash
SK="$HOME/.workbuddy/skills/sci-wechat-daily"

python "$SK/scripts/find_figs.py" "<论文.pdf>"
```

输出两段：① 每张图注在哪一页、图注标题的 y 坐标；② 每页的位图数 / 绘图数。

```
=== 图注定位（页号 | 图号 | 图注开头）===
p  2 | Fig. 1 | caption_y=432.8 | LPDs induce browning in a microbiota-dependent manner.
p  4 | Fig. 2 | caption_y=509.2 | ...

=== 每页 位图数 / 绘图数 ===
p  2  images=1     drawings=2147
p  3  images=0     drawings=8
```

三条路线的判据：

| 位图数 | 绘图数 | 结论 | 走哪条 |
|---|---|---|---|
| ≥1 | 少 | 位图主图 | `figtools detect`（§一） |
| 0~2 | **上千** | **矢量主图** | **本小节：渲染整页 + 按图注 y 裁剪** |
| ≈0 | ≈0 | Accepted Manuscript | §一之补 A |

**做法**（`crop_figs.py`，临时脚本，放 `.cache/`）：

```python
import pymupdf

fig_of_page = {2: 1, 4: 2, 6: 3, 7: 4, 8: 5, 9: 6}     # 由 find_figs.py 的输出整理
caption_y  = {2: 432.8, 4: 509.2, 6: 440.4, 7: 525.8, 8: 381.6, 9: 499.6}

doc = pymupdf.open(pdf)
for pno, fno in fig_of_page.items():
    pg = doc[pno - 1]
    cy = caption_y[pno]
    rect = pymupdf.Rect(0, 40, pg.rect.width, cy - 5)   # 上留 40pt 去页眉，下到图注上方
    pm = pg.get_pixmap(clip=rect, dpi=300)
    pm.save(f".cache/beige/p{fno:02d}.png")
```

- 上边界 `y0=40` 是为了**切掉页眉/页码/期刊跑边**；下边界 = 图注标题 y 减 5pt。
- `dpi=300` 是底线，低于此微信端看小字会糊。
- 页号是 **1-based**（`doc[pno-1]`），和 `find_figs.py` 输出一致。

**★ 图注跨页时，`caption_y` 有两个，别取错**：Nature 常见「图在本页，图注标题在本页底部起头、
正文转到下一页」，于是 `find_figs.py` 会打出两条：

```
p 20 | Extended Data Fig. 1 | caption_y=711.6 | See next page for caption.
p 21 | Extended Data Fig. 1 | caption_y= 47.7 | LPDs induce beige cells in iWAT. a, SPF B6 mice ...
```

- `y ≈ 700`（页尾）+ 图注开头是 `See next page for caption.` → **这条不能用来裁图**，
  它标的是"图注起始位置"，图本身在**前一页**
- `y ≈ 48`（页顶）→ 这是**图注页**，图也通常在**前一页**

**只取 `y` 在页面中部（比如 100 < y < 页高-150）、且图注开头是真实描述句子的那一条。**
主图（Fig. 1–6）一般不存在这个问题，Extended Data 高发。

**裁完还要切上下半**：Nature 主图普遍是「上排面板 + 下排面板」两栏，
整页塞进正文会太高（公众号里一张图超过一屏就要划很久）。
直接对半切最省事：

```python
from PIL import Image
im = Image.open(src)
w, h = im.size
im.crop((0, 0, w, h // 2)).save(out_top)          # R01_Fig1_上
im.crop((0, h // 2, w, h)).save(out_bottom)       # R02_Fig1_下
```

> **★ 切完必须看图确认中线切在哪。** 对半切是"最省事"不是"最正确"：
> 若上排面板底部还有一段说明文字或图例，会把它留在上半张；
> 若下排顶部顶到了图注，会白留一大截。**逐张打开核对**，必要时改用非对半的 y。

> **★ 别把 `Extended Data` 当主图。**
> `find_figs.py` 会同时列出 `Extended Data Fig. N`，它们是补充图，通常不放正文，
> 正文只讲主图（Fig. 1–6）。挑图时按 `Fig. N` 那一批走。

## 二、裁切与拼接

### spec.json 格式

```json
{
  "figures": { "F1": "<项目>/.cache/figs/p2_x130.png" },
  "boxes": {
    "F1_A": [120, 180, 640, 520],
    "F1_B": [660, 180, 1180, 520],
    "F1_C": [120, 540, 640, 880]
  },
  "jobs": [
    ["R1_Fig1_AB", [["F1_A", "F1_B"]]],
    ["R1_Fig1_C",  [["F1_C"]]]
  ],
  "width": 1200,
  "gap": 22,
  "margin": 10,
  "outdir": "<项目>/图片/裁切"
}
```

- `boxes` 的键名格式：`<图片代号>_<面板名>`，坐标是 `[x0,y0,x1,y1]`（像素，原图坐标系）
- `jobs`：每项 = `[输出文件名, [[第一行面板...], [第二行面板...]]]`
- 输出名建议 `R<节号>_Fig<图号>_<面板>.png`

```bash
python "$SK/scripts/figtools.py" compose "<项目>/.cache/spec.json"
```

### 裁图规则（★ 关键）

**每个面板先单独裁，再按行拼接。**

```
❌ 错误做法：按「横带」一刀切
   会切到相邻面板中间，或者把两个面板之间的空隙带进来

✅ 正确做法：逐面板裁 → 按行顶端对齐拼接 → 整行统一缩放到目标宽度
   每个面板都完整，且不会带进相邻面板
```

- 行内各面板**顶端对齐**（`paste` 到 y=0），高度不同时底部留白
- 整行拼接后**统一缩放**到 `width`（**只缩不放大**，`if out.width > width` 才 resize）
- 缩放用 `Image.LANCZOS`

## 三、像素级自检（★ 不可跳过）

```bash
python "$SK/scripts/figtools.py" verify <项目>/图片/裁切/*.png
```

**判据：亮像素比（灰度 > 200 的像素占比）必须 > 50%。**

```
R1_Fig1_AB.png: 1200x680 亮像素 92.3% OK
X_broken.png:    1200x0   亮像素  0.0% ★异常（疑似全黑/空图）
```

> **血泪教训**：曾因画布高度写错（`Image.new("RGB", (w, 0))` 之类）产出全黑封面，
> 而"用工具打开看图"**没有发现** —— 因为图看起来"就是一片黑"，被当成了正常深色设计。
> **看图 ≠ 验证图。** 每张生成图都要过这一步。

## 四、自制图（make_figures.py）

### 封面信息卡

```bash
python "$SK/scripts/make_figures.py" cover "<项目>/.cache/cover.json"
```

```json
{
  "out": "<项目>/图片/裁切/封面_论文信息卡.png",
  "journal": "Advanced Science",
  "meta": "Volume 12, Issue 3 | 2025",
  "title_en": "Quercetin alleviates obesity via Akkermansia muciniphila",
  "title_zh": "槲皮素经 Akkermansia muciniphila 改善肥胖的机制研究",
  "authors": "Zhang San, Li Si, Wang Wu",
  "affils": "1. 中国农业大学动物科技学院；2. 山西农业大学动物科学学院",
  "doi": "10.1002/advs.202400001",
  "date": "2025-01-15",
  "width": 1400
}
```

- `title_en` / `title_zh` / `authors` / `affils` 会**自动折行**：标题英中各截 2 行，
  **作者最多 4 行、单位最多 3 行**
- **★ 作者要写全，别写「等 N 位作者」**（用户明确要求过）。多作者会折成 2–4 行，
  卡片高度按**实际行数**自动增长 —— 早期版本把作者区固定按 1 行预留高度，作者一多就会压掉单位行，已修
- `width` 默认 1400；高度由内容自动计算
- 视觉：顶部深蓝色带 + 期刊名突出 + 分隔线 + 英文标题（大）+ 中文标题（次） + 作者/单位 + DOI（左）/日期（右）

### 技术路线图

```bash
python "$SK/scripts/make_figures.py" roadmap "<项目>/.cache/roadmap.json"
```

```json
{
  "out": "<项目>/图片/裁切/技术路线图.png",
  "title": "研究思路与技术路线",
  "stages": [
    {"name": "玛咖粉成分分析", "bullets": ["常规营养成分", "总酚、总黄酮", "抗氧化活性", "酚酸与玛咖酰胺"]},
    {"name": "饲养试验",       "bullets": ["40 头后备母猪", "均重 29 kg，随机分两组", "108 天，分两期饲养", "按栏算 DFI、FCR"]}
  ],
  "width": 1100
}
```

- **★ 每个环节 3–4 条要点分行写，不堆成长段**（2026-10-23 用户明确；旧版「一环节一长句」
  会把字挤成一坨，手机上读不动，已返工过一次）。新 spec 用 `stages`（name + bullets），
  旧 `steps`（每环节一条长句）仅兼容保留
- 要点写**测了什么 / 做了什么**，不写"怎么测的"——多种方法检测、HPLC、屠宰这类
  共识性操作细节省略（与 THINK 段同口径）
- **★ 字号不用手调**：脚本按「微信正文显示宽度 677px」反推字号
  （`字号 = round(width × 12.5 / 677)`）。判据：**图上看着大没用**，
  要看 `字号 × 677 / 画布宽` 换算后的实际值 ≥ 12px 才读得清。
  事故记录：1080px 画布配 14px 字 → 实际只有 8.6px，被判「字有点小」返工
- 折行规则（脚本内置）：中文逐字、拉丁词整词不断行（TEAC/DFI 不拆），末行 1–2 字孤行自动回填，
  **标点不落行首**（「、 FCR」这类断行由避头点逻辑自动回挪——2026-10-23 补）
- 横向排列：圆角卡片 + 编号圆点 + 环节名 + 要点圆点列表 + 卡片间箭头
- 生成后必看一眼成图：防右侧溢出（4 卡宽度要算上 margins + gaps）、防标题与要点重叠

### 上标写法（★ 重要）

```
"10{^9} CFU/mL"      →  渲染成 10⁹ CFU/mL
"mg kg{^-1}"         →  渲染成 mg kg⁻¹
```

**原因**：Windows 的微软雅黑等中文字体**没有 `⁹`（U+2079）、`⁻`（U+207B）等上标字形**，
直接写进字符串会渲染成方框/豆腐块。`make_figures.py` 会把 `{^...}` 里的内容
按 0.68 倍字号、上移 0.36 倍行高单独绘制，得到真正的上标。

### 二维码

```bash
python "$SK/scripts/make_figures.py" qr "<原二维码>" "<项目>/图片/裁切/关注二维码.jpg"
```

处理三步：① 二值化找内容包围盒、裁掉多余白边 → ② 补标准静默区（约 4 模块宽）→ ③ 缩放到 900×900。

**只需做一次**，之后每篇复用同一张。输出建议用 `.jpg`（体积小，二维码不需要无损）。

```

├── 图片/

│   └── 裁切/
│       ├── 封面_论文信息卡.png        ← 自制，无图注
│       ├── 技术路线图.png             ← 图1
│       ├── R1_Fig1_AB.png            ← 结果图，图2 起
│       ├── R2a_Fig2_CD.png

│       └── 关注二维码.jpg             ← 无图注
└── .cache/                           ← 中间产物，任务结束清理
    ├── figs/                          ← detect 输出
    ├── spec.json                      ← compose 输入
    └── cover.json / roadmap.json
```

| 类型 | 命名 | 图注 |
|---|---|---|
| 封面信息卡 | `封面_论文信息卡.png` | **不写** |
| 技术路线图 | `技术路线图.png` | `研究思路与技术路线`（自动成「图1」） |

| 结论示意图 | `机制总结图.png` 或 `R5d_Fig5_O机制图.png` | `机制总结图（原文 Figure 5O）`；用首页 Graphical Abstract 时写 `机制总结图（原文 Graphical Abstract）`。**原文没有 → 结论章不放图，禁止自绘**（CANON 第 8 条） |
| 二维码 | `关注二维码.jpg` | **不写** |

## 七、坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 全黑图 | 画布高度写错，越界被黑填充 | 必跑 `verify` |
| 裁图切到面板 | 按横带裁 | 逐面板单独裁 → 按行拼接 |
| 上标变方框 | 字体缺 `⁹⁻` 字形 | 写 `{^9}`，让脚本手绘上标 |
| 面板编号错位 | 跨栏/合并跨行面板 | 人工核对 `annot_p*.png`，手改 `boxes` 坐标 |
| 抽出的是 logo | 未做尺寸过滤 | 已在 `detect` 里跳过 < 页面宽 50% 的图 |
| 图注编号断号 | 手写编号 | 编号由 `build.py` 自动递增，内容文件不写编号 |
| `detect` 一张图都没找到 | 主图是**矢量绘图**，detect 只看内嵌位图 | 先跑 `find_figs.py` 判版式，走 §一之补 C |
| 抽到的全是补充图 | `Extended Data` 与主图混在一起 | 只取 `Fig. N`，Extended Data 一般不放正文 |
| 末图是一堆条带/柱子 | 拿结果面板顶了结论图 | 结论图必须是原文示意图（正文机制图 → 首页 Graphical Abstract）；都没有就不放图，**禁止自绘**（CANON 第 8 条） |
| 图与图注对不上 | 提图、裁切、写注三步分离，无人对账 | 走 §八 图-注对账终审 |
| 路线图字太小 | 画布宽、字号按原图看着够 | 按「字号 × 677 / 画布宽」换算实际显示值，≥ 12px 才合格；用 `stages`（要点分行）spec |

## 八、图-注对账（终审，★ 不可跳过）

**这是 SKILL.md 第 7 步的图片侧细则。** 交稿前最后一道关，只查一件事：
**每张图的内容，与它的图注声称的内容是否相符。**

> `verify` 只能查出全黑/空图，查不出「编号对、内容错」。
> 2026-10-22 两次事故都漏在这里：图注写「原文 Figure 2 下半部分」、实际插的是另一处面板；
> 结论章放了自绘流程图而 PDF 首页本来就有 Graphical Abstract。

### 做法

1. **列对账表**：从内容文件抽出全部图片，一行一图：

   ```
   图文件                        图注声称                PDF 出处
   R3_Fig3_A.png                Figure 3A              p.5
   R5d_Fig5_O机制图.png          原文机制图 / Graphical Abstract   p.1 或机制图所在页
   ```

2. **逐张开图核对**（自制图除外）：
   - 图注写 Figure 3A → 图里必须是 3A 的内容；写「Figure 2 下半部分」→ 必须正是那半张
   - 拿不准就回 PDF 对应页并排比对（`find_figs.py` 的图注定位输出可当页码索引）
   - 对不上只有两种修法：**换正确的图** 或 **改图注**，不许将就
3. **结论图单独判**：必须是原文示意图（正文机制图 → 首页 Graphical Abstract）；
   两处都没有 → 结论章不放图（`CONCLUSION_IMG = ""`）。**禁止自绘**
4. **自制图核对文字**：封面卡的标题/作者/DOI、路线图的步骤与本文一致
   （防复用上期文件没改干净）

### 为什么必须放在最后

提图（第 1 步）、裁切（第 2 步）、写注（第 5 步）由三个环节完成，
中间没有任何一步天然做「图 ↔ 注」对账；成稿时距提图往往已隔很久，靠记忆必然错配。
**只有成稿后拿成品逐张回对原文，才能闭环。**
