# 写作规则（写稿前必读）

## 一、标题怎么定（落笔第一步）

标题固定形态：**《期刊名》｜署名部分 + 一句话核心发现**

变的是「署名部分」。**先判属于哪种情况，再落笔**；判不出来就走情况 C。**宁缺毋滥。**

### 判定流程

```
① 读 PDF 首页：作者列表 + 单位上标 + 通讯作者标记（* †）
        ↓
② 主通讯作者 = 作者列表最后一位（通行惯例）
        ↓
③ 主通讯的单位 == 第一作者的单位 ？
   ├─ 是  → 情况 A
   └─ 否  → 先做 ④；④ 也没查出知名学者 → 情况 C
        ↓
④ 通讯作者是不是只有一位？
   ├─ 是  → 按 ③ 的结论走
   └─ 否  → 逐个查（不论排第几），查出知名学者 → 情况 B
```

### 情况 A ｜ 主通讯单位 = 第一作者单位

**格式**：`《期刊》｜单位 + 姓名 + 团队 + 核心发现`

> 《Advanced Science》｜浙江大学王新霞团队揭示槲皮素经"肠道菌—胆汁酸"轴改善肥胖的新机制

- 单位写**一级单位简称**（「浙江大学」，不写「浙江大学动物科学学院」）
- 姓名后接「团队」；**职称默认不写**。用户明确指定时才加（如「于太永教授团队」）
- 核心发现压缩成一句，动词取中性的「揭示 / 阐明 / 发现 / 构建」

### 情况 B ｜ 通讯作者中有知名学者

**只要有多位通讯作者，就必须逐个查**——不能只看排位。

| 关系 | 写法 |
|---|---|
| 知名学者与主通讯**同单位** | 《期刊》｜单位 + **某某院士团队** + 核心发现 |
| 知名学者与主通讯**不同单位** | 《期刊》｜某某教授**联合**某某院士团队 + 核心发现 |

**「知名学者」判据**（按可信度排序）：

1. 中国科学院 / 中国工程院 **院士** —— 最硬，两院官网有名单可查
2. 国家最高科学技术奖、国家自然科学奖一等奖获得者
3. 其他公认头衔（国家杰青、长江学者、国家奖第一完成人）—— 可写，但**必须能查到官网页面或官方公示佐证**；
   只见于商业百科、新闻稿的不写

**查法**（顺序即优先级，下面是可信度从高到低）：

1. 该学者所属单位的**官网教师主页 / 课题组页 / 院士名单页**
2. 单位官方新闻、人才办或人事处公示
3. 中国科学院 / 中国工程院官网的院士名单
4. 学会官网、权威期刊编委页

> 商业百科（百度百科等）只能当**线索**，不能当**依据**——找到线索后必须回到官网核实。

### 情况 C ｜ 通讯作者不在第一作者单位，且查不到其官方个人介绍

**标题不出现单位和作者，直接描述文章内容。**

> 《Briefings in Bioinformatics》｜长读长测序下胚系与体细胞结构变异检测的综合评测

- **判据**：在该通讯作者所属单位的官网上，检索不到其个人介绍页 / 课题组页 / 教师名录条目
- **为什么**：标题署名是事实性陈述。单位、职称查不实就可能写错，**宁可只描述内容，不可猜、不可拼凑**
- **注意**：情况 C 只影响**标题**。正文的论文信息块照常列作者与单位——那里的信息直接取自 PDF 首页，属原文内容

### 常见错误

| 错法 | 为什么错 |
|---|---|
| 把第一作者当成署名对象 | 标题署的是**课题组 / 通讯作者**，不是第一作者 |
| 只查主通讯，漏掉其他通讯里的院士 | 多位通讯时必须逐个查，知名学者要列出 |
| 凭印象写单位 | 单位名必须回原文上标 + 官网核对 |
| 查不到作者就只删作者、留下单位 | 情况 C 是**两者都不写**，不能只留一半 |
| 标题里给基因名加 `<i>` | `<title>` 与 meta 不支持富文本，`build.py` 会剥掉标签 |
| 标题过长 | 微信标题有长度限制，实测 81 字可用；**超过约 90 字要精简** |

## 二、语言与立场

| 规则 | 具体要求 |
|---|---|
| **客观主语** | 一律用「研究 / 本研究 / 该研究」；**严禁「我们」**；不用「作者……」作叙述主语 |
| **禁用句式** | 「我们发现了」「研究者发现」「作者发现」→ 改「该研究发现」「研究显示」 |
| **纯转述** | 不添加原文没有的推论、展望、应用建议、编者观点 |
| **假说标注** | 原文的「推测 / 可能」必须保留为假说，不得写成「证明」 |
| **小标题** | 用陈述句，不带情绪词（不用「震惊」「颠覆」「终于」） |
| **不写方法论建议** | 不出现「你可以照抄」「建议用这种方法」这类面向读者的建议 |

## 三、研究背景：四步推进（本项目特有写法）

由浅入深、由宏观到具体。**顺序固定，四段各自职责明确**：

| 段 | 内容 | 推进方向 |
|---|---|---|
| **1. 基础背景** | 领域大背景 + 已被广泛接受的共识 | 宏观 |
| **2. 研究现状** | 本课题方向已有线索分别进展到什么程度 | 收窄 |
| **3. 存在的问题** | 哪些关键环节尚未阐明、缺乏直接证据 | 聚焦缺口 |
| **4. 本研究做了什么** | 本研究从哪个角度切入、做了什么、得到什么结论 | 落到本研究 |

**示例（结构示范，内容须替换为本文自己的）**：

```
① 肥胖已成为全球性公共卫生问题，肠道菌群失调被广泛认为参与其发生发展。
② 已有研究报道，膳食多酚可改善代谢紊乱，且其作用常与特定肠道菌群的变化同时出现。
③ 然而，多酚究竟通过哪一菌种发挥作用、该菌种是否构成因果环节，尚缺乏直接证据。
④ 本研究以高脂饮食诱导的肥胖小鼠为模型，探究了槲皮素对肠道菌群组成的影响，
   并通过菌群移植验证了 Akkermansia muciniphila 在其中的因果作用。
```

### ⚠️ 只借「写法」，不借「内容」

若用户给了一篇**参照文**说"照这个写法写"，含义是**借鉴结构顺序**，
**内容必须全部来自本期这篇论文**。

> 曾发生过的事故：把参照文（另一篇论文，讲金华猪体脂表型）的**内容**写进了本期研究背景。
> 交稿前自检应扫一遍研究背景，确认没有其他论文的关键词混入。
> **不确定时先问用户**：是"换一篇论文接着做"，还是"借这篇的写法"？

## 四、结果部分

| 规则 | 做法 |
|---|---|
| **不逐句翻译** | 一个小标题 = 原文一个 Results 小节，写成一整段「做了什么 → 得到什么」 |
| **不写面板引用** | 正文不出现「（图1A）」「如图 2B 所示」这类字样 |
| **面板细节下沉图注** | 图注里写明对应原文图号与面板范围 |
| **配图只截关键面板** | 不整张放；用 PDF 原生位图裁切，**不做二次重绘** |
| **图注格式** | `一句话概括（原文 Figure 2A–G）` —— 单行、不加评价、不逐面板说明 |

**图注编号由 `build.py` 自动递增生成，内容文件里只写文字、不写「图N」。**

### ★ 末图（结论图）必须是机制总结图，不能复用结果面板

`CONCLUSION_IMG` 是**结论章那张图**，读者看它是为了「一眼看懂整条通路」。判据：

- ✅ 原文确实有一张**通路/模式图**（示意性，画的是箭头与关系链）
- ❌ 拿某张结果图的**下半部分**顶上 —— 那仍是**验证性数据面板**（Western blot / 柱状图 / qPCR），
  不是机制总结

**踩过的坑**：Nature 那篇主图按上下半切成了 12 块，末图顺手取了 `R12_Fig6_下`，
结果那是突变株验证面板，读者翻到结尾看到的仍是一堆条带，而不是"本文讲了个什么机制"。

**原文没有示意性机制图时的做法**：用 Pillow **自绘一张**（`make_mech.py`，放 `.cache/`）。
要点：

- 画布底色取**当期版式的背景色**（版式 E 是 `#fbfaf7`），别用纯白，否则在纸感背景上突兀
- 结构照抄原文的因果链：上游（饮食/菌群）→ 中介（代谢物/受体）→ 效应（表型）
- **两条通路要画成并行汇合**，并在图上注明「非冗余」这类关键限定 —— 这正是原文的结论
- 自绘图**同样要过 `figtools verify`**（亮像素比 > 50%，防全黑画布）

## 五、论文信息块

- **全篇只出现一次**，放结尾
- 只写：期刊名、纯日期、DOI、第一作者姓名、通讯作者姓名、单位
- **不带括号备注**（如不写「（共同第一作者）」）
- **共同第一/通讯作者必须核实**：
  判据 = 作者行符号 + 全文检索 `† ‡ § # ¶`；原文没标注就**不加**

`content_<篇名>.py` 里：

```python
INFO = [
    ("期　　刊｜", "Advanced Science"),
    ("发表日期｜", "2025 年 1 月 15 日"),
    ("D O I　｜", "10.1002/advs.202400001"),
    ("第一作者｜", "Author Name"),
    ("通讯作者｜", "Author Name"),
    ("主要单位｜", "单位一；单位二；单位三"),
]
```

## 六、数字核验（★ 必做）

正文里出现的**每一个数字**都必须能在原文找到唯一出处。

### 上标陷阱

```python
# 错：get_text() 会把上标吞掉 —— 10⁹ 读成 109、mg kg⁻¹ 读成 mg k−1g
page.get_text()

# 对：用 span 字号判断，字号明显偏小的才是上标
for blk in page.get_text("dict")["blocks"]:
    for line in blk["lines"]:
        for s in line["spans"]:
            print(repr(s["text"]), s["size"])
```

**凡剂量、指数、单位负幂，落笔前必须这样核一次。**

### 常见易读错项

| 原文 | `get_text()` 误读 | 正确 |
|---|---|---|
| `10⁹ CFU/mL` | `109 CFU/mL` | `10⁹ CFU/mL` |
| `mg kg⁻¹` | `mg k−1g` | `mg kg⁻¹` |
| `P < 0.05` 上标 `a` | `P < 0.05a` | 保留上标含义 |

## 七、术语、格式与文末声明

### 7.1 术语怎么译（★ 先判再用）

**读者是研究者，不是大众。** 判断标准不是「哪个更通俗」，而是**「目标学科的中文文献里约定俗成怎么写」**。

三步判定：

1. **有没有规范定名** —— 全国科学技术名词审定委员会公布的名词、权威译著、国家级教材优先
2. **目标学科的高频用法是什么** —— 同一英文词在不同学科可能定名不同（见下表 germline）
3. **直译会不会产生歧义** —— 会就换更准的说法；不会就保留学科定名

**★ 铁律：不为「通俗易懂」牺牲学科定名。**
生信读者看到「生殖细胞突变」会觉得译得不专业，看到「胚系突变」才对味。**术语的专业性本身就是可信度。**

**已定名的例子**（可直接沿用）：

| 英文 | 采用 | 说明 |
|---|---|---|
| germline | **胚系** | 中文基因组学 / 变异检测领域的通行译法，与「体细胞」成对出现。别名有生殖细胞、种系、生殖系等（科学出版社《人类癌症遗传学实用指南》译本列出 7 种）。**肿瘤与变异检测语境下一律用「胚系」** |
| somatic | **体细胞** | 无争议 |
| structural variation (SV) | 结构变异 | 与「单核苷酸变异（SNV）」并列 |
| benchmark | 基准评测 | 评测类论文标题常用 |

成对出现的术语，**两边用法要一致** —— 不能一边「胚系」一边「生殖细胞」。

### 7.2 格式

| 项 | 规则 |
|---|---|
| 专业术语 | 首次出现写「中文（英文）」，如「法尼醇X受体（FXR）」；同一术语后续只写中文 |
| 基因名 | 斜体，HTML 用 `<i>...</i>`，如 `<i>Muc2</i>` |
| 拉丁学名 | 斜体，如 `<i>Akkermansia muciniphila</i>` |
| DOI | 必须附，写在信息块 + 标题副行 |
| 样本量 n | **不标**（用户明确要求；需要时再加回） |
| 单位 | 保留原文单位，不换算 |

> ⚠️ **批量加 `<i>` 前先保护文件路径**：`R13_上皮与ASXL1.png` 会被误改成 `R13_上皮与<i>ASXL1</i>.png`。
> 批量替换后**必须重跑 `build.py`** —— 它的缺图校验会当场抓出来。

### ★ 缩写：每一个都要在「全文首次出现处」给中文全称

不只要给，**给的位置必须对**：首次出现 = **阅读顺序上的第一次**（总述 → 研究背景 → 结果 3.1 → 3.2 …），
不是"每个章节里第一次"。写在 3.4 才给全称、而 3.1 就已经裸奔，等于没给。

**自查办法（别靠眼睛扫）**：把正文里所有 `A-Z` 连续大写串抽出来去重，逐个回查首次出现位置。

```python
import re, collections
txt = open("版式E_墨绿纸感.html", encoding="utf-8").read()
txt = re.sub(r"<[^>]+>", "", txt)          # 去标签
abbr = collections.Counter(re.findall(r"\b[A-Z][A-Za-z0-9]{1,7}\b", txt))
for a, n in sorted(abbr.items()):
    i = txt.find(a)
    print(f"{a:<10} {n:>3}次  首次: ...{txt[max(0,i-40):i+len(a)]}...")
```

看到 `LPD 12次 首次: ...低蛋白饮食...` 这种就说明**漏了全称**（首次出现是裸的 `LPD`）。

**易漏的三类**：

| 类型 | 例子 | 怎么处理 |
|---|---|---|
| 实验材料缩写 | GF（无菌）、SPF、LPD、CD（对照饲料）、HFD | 第一次写「无菌（germ-free，GF）小鼠」 |
| 组学/检测缩写 | snRNA-seq、FDG-PET、BSH、7αHSDH、qPCR | 第一次写「单核 RNA 测序（snRNA-seq）」 |
| 菌群/分类名 | BEEO、RL、BEE 这类作者自造的分组代号 | **必须解释分组是怎么来的**：19 株 BEEO = 拟杆菌属 + 肠球菌属 + 丹毒丝菌科 + 其他门，别只写"19 株菌" |

> **踩过的坑**：把 `19 BEEO` 译成「拟杆菌门 / 肠球菌纲」，属和门/纲的层级直接错了。
> 分类层级（门 phylum / 纲 class / 目 order / 科 family / 属 genus / 种 species）**必须回原文核**，
> 中文名后缀有暗示：*-aceae* = 科，*Bacteroides* = 拟杆菌**属**，*Bacteroidetes* = 拟杆菌**门**。

### 7.3 文末 AI 声明（**默认不加**）

**当前口径：正文不加 AI 声明**。若某期需要，在内容文件里写：

```python
AI_NOTE = "本文的文献搜集、整理与分析由人工完成，AI 仅参与辅助解读，最终内容经人工复核。"
```

`build.py` 会把它插在**论文信息块之后、「欢迎关注」之前**；不写或写成 `""` 都不加。

- 全篇**只此一处**；正文其他位置不出现 AI 标识、免责声明、审查结论
- 若加了，位置落在**末尾**，也可对应《AI 生成合成内容标识办法》第四条「起始、末尾或中间适当位置」

## 八、一段话总述（LEAD）怎么写

全文压缩成一段，**只回答两个问题**：

1. **做了什么** —— 研究用什么模型/方法、针对什么问题
2. **发现了什么 + 意味着什么** —— 核心结论一句话

控制在 100–140 字。这段会被 `build.py` 抽成公众号摘要（`wx-digest`），
所以**不要出现 HTML 标签、不要出现双引号**（会破坏 meta 属性）。
