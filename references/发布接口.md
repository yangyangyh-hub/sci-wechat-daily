# 微信公众号发布接口

## 一、先说结论

| 事项 | 结论 | 证据等级 |
|---|---|---|
| 个人未认证订阅号 ⇒ `draft/add`（进草稿箱） | ✅ **可以** | 一手（本机实调） |
| 个人未认证订阅号 ⇒ `freepublish`（直接群发） | ❌ **不行** | 一手（官方文档原文） |
| 秀米有开放 API / MCP | ❌ 没有。不开放编辑器 SDK | 二手（社区答复）+ 官方协议未见 |
| 微信 `media/uploadimg`（正文图） | ✅ 个人号可用 | 一手（本机实调） |
| 微信 `material/add_material`（封面） | ✅ 个人号可用 | 一手（本机实调） |
| 出口 IP | **动态漂移**，必须加白名单 | 实测 |

**所以链路是：脚本建草稿 → 人工到后台点群发。**

---

## 二、接口链路

```
① GET  cgi-bin/token?grant_type=client_credential&appid=&secret=
        → { access_token, expires_in: 7200 }        ← 有效期 2 小时

② POST cgi-bin/media/uploadimg?access_token=      （multipart，字段名 media）
        → { url: "http://mmbiz.qpic.cn/..." }       ← ★ 返回 http，必须改 https

③ POST cgi-bin/material/add_material?access_token=&type=image   （multipart）
        → { media_id: "..." }                       ← 封面素材

④ POST cgi-bin/draft/add?access_token=   （JSON）
        body: { "articles": [ { title, author, digest, content,
                                content_source_url, thumb_media_id,
                                need_open_comment, only_fans_can_comment } ] }
        → { media_id: "..." }                       ← 草稿建立成功

⑤ POST cgi-bin/draft/batchget?access_token=   { offset:0, count:20, no_content:1 }
        → 读草稿列表，可取回草稿的临时预览 url

⑥ POST cgi-bin/draft/delete?access_token=   { media_id }
        → { errcode: 0 }
```

**`content` 字段**直接放 HTML 片段（不带 `<!DOCTYPE>/<head>/<body>` 外壳）。
`build.py` 生成的 HTML 里用注释标记了正文起止，`publish.py` 的 `strip_outer()` 会自动切出来。

## 三、实测记录（2026-10-10）

| 步骤 | 结果 |
|---|---|
| 换 access_token | ✅ 成功（`expires_in: 7200`） |
| 空 `thumb_media_id` 建草稿 | 返回 `40007 invalid media_id` ← **关键证据** |
| `media/uploadimg` 上传正文图 | ✅ 返回 `mmbiz.qpic.cn` URL |
| `material/add_material` 上传封面 | ✅ 返回 `media_id` |
| `draft/add`（带封面） | ✅ 返回 `media_id`，`batchget` 读回验证通过 |
| `draft/delete` | ✅ `errcode: 0` |

### ★ 权限判据

```
48001 api unauthorized   ⇒ 鉴权阶段就被拒 ⇒ 真的没有权限
40007 invalid media_id   ⇒ 已通过鉴权、进入业务校验 ⇒ 有权限，只是参数不全
```

**社区流传的"个人号调 `draft/add` 返回 48001"对本账号不成立** ——
实测一直返回 `40164`（IP 未白名单），被误传成了权限问题。

## 四、错误码速查

| 错误码 | 含义 | 处理 |
|---|---|---|
| `40164` | IP 不在白名单 | 把返回提示里的 IP 加进后台白名单 |
| `40125` | AppSecret 不正确 | 核对凭据文件；必要时在后台重置 |
| `40013` | AppID 不正确 | 核对凭据文件 |
| `40007` | 参数错误（多为封面 `media_id` 无效/缺失） | 脚本会自动传封面；仍报错检查封面图是否合规 |
| `48001` | api unauthorized | 真的无权限（本流程不应出现） |
| `45009` | 接口调用频率超限 | 等待后重试 |
| `40001` | access_token 无效 | token 过期或被顶掉，重新获取 |

## 五、IP 白名单（最容易卡住的一步）

**位置**：公众号后台 → 设置与开发 → 开发 → 基本配置 → IP 白名单

**现象**：换 token 时报

```
{"errcode":40164,"errmsg":"invalid ip 60.223.239.x ipv6 ::ffff:60.223.239.x, not in whitelist"}
```

**处理**：错误信息里已经写明了当前 IP，把它加进白名单再重试。

**注意**：家庭宽带出口 IP 是**动态**的，会不定期漂移（历史见过 `.6 / .7 / .8`）。
所以这不是"配置一次就永久生效"的事，换网络、重启路由器、运营商重新分配都可能变。
如果频繁遇到，可在白名单里填一个**连续网段**（如 `.6`–`.15`）。

**自检命令**：

```bash
python "$SK/scripts/publish.py" --env <凭据文件> --check
```

成功输出：`✅ access_token 获取成功` + `✅ 接口连通，草稿箱可访问`

## 六、凭据管理（★ 安全须知）

### 怎么给

`publish.py` 按优先级找凭据：

1. `--env <文件路径>`
2. 环境变量 `WX_APPID` / `WX_APPSECRET`
3. 环境变量 `WX_ENV_FILE` 指向的文件
4. 依次搜索 `./.env` → `~/.wechat.env` → `~/.workbuddy/wechat.env` → `~/wechat.env`

文件格式（键名大小写不敏感，中英文冒号都认）：

```
AppID：wx1234567890abcdef
AppSecret: 0123456789abcdef0123456789abcdef
```

正则：`AppID\s*[：:=]\s*(\S+)` —— 所以 `AppID：`、`AppID:`、`AppID =` 都能识别。

### 从哪拿

公众号后台 → 设置与开发 → 开发 → 基本配置

- **AppID** 长期固定，直接复制
- **AppSecret** 需点「重置」生成，**重置后旧密钥立即失效**，页面上只显示一次，**必须当场记下来**

> 个人未认证订阅号**也能**生成 AppSecret —— 这一点曾被误判为"个人号没有"，实测证伪。

### 安全规则

| 规则 | 原因 |
|---|---|
| **AppSecret 是账户级最高权限** | 能调本号所有接口，泄露等于账号被接管 |
| **不要截图、不要粘贴到聊天里** | 图片和文字都会留在记录中，可能被再次读取 |
| **不要写进任何脚本或模板** | 本技能的所有文件都不含凭据，就是为了可安全分享 |
| **一旦出现在记录中，立即重置** | 后台一键重置，重置后旧的立刻作废 |
| **存在用户自己的 `.env` 里** | 脚本每次读取，用户可随时更换 |

## 七、网络坑

### TLS 握手失败

**现象**：调微信接口报 SSL/TLS 错误（curl 表现为 exit 35）。

**原因**：shell 环境注入了会话代理（`HTTP_PROXY` / `HTTPS_PROXY`），
代理隧道到微信 API 时返回 502。

**解法**（`publish.py` 已内置）：

```python
# 建一个不使用任何代理的 opener
OPENER = urllib.request.build_opener(urllib.request.ProxyHandler({}))
```

用 `curl` 手工调试时加 `--noproxy "*"`。

### 微信图片 URL 是 http

`media/uploadimg` 返回 `http://mmbiz.qpic.cn/...`，而公众号正文要求 https。
`publish.py` 里已统一处理：

```python
return r["url"].replace("http://", "https://", 1)
```

## 八、兜底路径（接口不通时）

若 IP 漂出白名单、或临时换网络导致接口完全不通：

1. 浏览器打开生成的 HTML
2. `Ctrl+A` 全选 → `Ctrl+C`
3. 粘贴进公众号后台编辑器（图片随剪贴板一起过去）
4. 手动设置封面、标题、摘要

**这条路径永远可用**，不依赖任何接口和凭据。

## 九、AI 内容标识（合规）

《人工智能生成合成内容标识办法》（国信办通字〔2025〕2 号）**已于 2025-09-01 施行**：

- 第四条：文本应在**起始、末尾或中间适当位置**添加文字提示等**显式标识**
- 第十条：用户发布生成合成内容时，应当**主动声明**并使用平台提供的标识功能

**本项目当前口径（2026-10-15 用户决定）：默认不加。**
`build.py` 的 `DEFAULT_AI_NOTE` 为空串；内容文件不写 `AI_NOTE` 或写成 `""` 时，正文不出现任何声明。
某期需要时，在内容文件里写：

```python
AI_NOTE = "本文的文献搜集、整理与分析由人工完成，AI 仅参与辅助解读，最终内容经人工复核。"
```

`build.py` 会把它插在**论文信息块之后、「欢迎关注」之前**（末尾位置，对应第四条「起始、末尾或中间适当位置」）。
全篇**只此一处**；除此之外不出现其他 AI 标识、免责声明、审查结论。
发布时若后台另提供「AI 生成」声明选项，**一并勾选** —— 平台标识与正文文字标识并行，不冲突。

> 变更记录：2026-10-15 曾改为「文末加一句」；同日用户再次决定**去掉**，改为默认不加、按需开启。
> 合规口径以用户当期决定为准，机制（内容文件 `AI_NOTE` 一个开关）保持不变。
